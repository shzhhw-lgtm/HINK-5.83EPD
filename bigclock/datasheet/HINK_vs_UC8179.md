# HINK-E0583A51-A0 手册 vs UC8179 手册：差异与勘误

> 对比对象
> - `datasheet/HINK-E0583A51-A0.pdf`（HOLITECH，A0，51 页，2023-08）
> - `datasheet/UC8179.pdf`（UltraChip UC8179c_C0.6，81 页，2019-11）
> - 本屏板载 OTP：`datasheet/HINK-E0583A51-A0_OTP.txt`

## 结论先行

1. **两份文档不是同一层级**：UC8179 是驱动 IC 规格书；HINK 是模组规格书，把 IC 手册的大半本复印过来，再补机械/光学/可靠性。
2. **HINK 的指令码没有抄错**：命令表 59 个十六进制码按顺序逐项比对，与 UC8179 完全一致。
3. **HINK 真正的问题不在指令，而在“默认值”**：它列的是 IC 复位默认值（三色模式、800×600、14V、HST=0），不是这块屏 OTP 里烧的值。照它初始化会直接跑偏。
4. **最关键的三节它没有**：OTP 地址映射、命令默认值表、OTP 里的 LUT 格式，恰好是驱动这块屏必须的。所以 HINK 手册不能替代 UC8179 手册，更不能替代 OTP。

一句话：**当“模组机械/接口手册”用可以，当“驱动开发手册”用会踩坑。**

## 1. 定位差异

| 项目 | UC8179.pdf | HINK-E0583A51-A0.pdf |
|---|---|---|
| 性质 | 驱动 IC 规格书 | 模组规格书（IC 内容 + 面板内容） |
| 页数 | 81 | 51（实际内容到 52 页） |
| 指令表 | 完整、编号连续 | 有，但编号错位（见 §3） |
| 指令详细描述 | 有 | 有，基本逐字照搬 |
| OTP 地址映射 | 有（P47） | **没有** |
| 命令默认值表（0x000C~0x001E） | 有（P50） | **没有** |
| OTP 内 LUT/TR 格式 | 有（P51） | **没有** |
| SPI 时序数值（100ns/35ns…） | 有（P58~59） | **没有**（只有格式图） |
| 机械图 / FPC 引脚 | 没有 | 有（P5~7） |
| 光学 / 可靠性 / 包装 | 没有 | 有（P41~52，但后半段串页） |

## 2. HINK 可信、且与 OTP 吻合的部分

| 参数 | HINK 值 | 核对结果 |
|---|---|---|
| 分辨率 | 648(H)×480(V) | 与 OTP `0x0016~18` 一致（648×480）✔ |
| 有效区 | 118.78×88.22 mm | 648×0.1833≈118.78 ✔ |
| 外形 | 125.4×99.5×1.10 mm | 5.83" 合理 ✔ |
| 像素 | 1-bit 黑白 | 与 OTP `PSR.KW/R=1`（KW 模式）一致 ✔ |
| 接口 | BS=L → 4-wire SPI | 与接线一致 ✔ |
| BUSY_N | 低=忙，忙时不要发命令 | 与实测一致 ✔ |
| 温度 | 工作 0~50°C，存储 -25~60°C | 面板级指标，合理 ✔ |
| 功耗 | 刷新 11mA，深睡 3µA | 量级合理 ✔ |
| VCOM | P37 明确写“VCOM 由工厂烧进 OTP 或贴标签” | 直接支持“从 OTP 取 VCOM=-1.0V” ✔ |

> 注意：HINK 的“Panel DC Characteristics”（P37）**根本没有列 VSH/VGH/VSL/VGL/VCOM 的具体电压**。
> 这等于承认：驱动电压只在 OTP 里，文档给不了。

## 3. HINK 明确错误 / 自相矛盾的地方

| # | 页码 | 问题 | 证据 |
|---|---|---|---|
| 1 | **P47~52** | 页眉型号变成 **HINK-E075A32**（7.5"），不是本型号 | P47、P48、P49、P50、P51、P52 页眉全部是 `HINK-E075A32` |
| 2 | **P48** | 外形写成 **170.20×111.20 mm**，与 P4 的 125.4×99.5 自相矛盾 | 170.2×111.2 是 7.5" 面板尺寸，明显串页 |
| 3 | **P42** | 光学特性写 `WS: White, DS: Dark, RS: Red` | 本屏是黑白 KW，没有红态，是从三色手册抄来的 |
| 4 | **P8~9** | DTM1/DTM2 标注 `(800x600)` | 这是 IC 默认示例；本屏是 648×480，照抄会配错 TRES |
| 5 | **P11 vs P27** | 同一命令编号不一致：命令表里 TRES 是 **#32**，描述里是 **(26)**；GSST #33/(27)、REV #34/(28)、FLG #35/(29) 整体偏 6 | 文档内部编号没有对齐 |
| 6 | **P37** | “characteristics are only guaranteed under the controller & waveform provided by **XingTai**” | HOLITECH/HINK 的文档里出现第三方厂名，属复制残留 |
| 7 | **P36** | 参考电路 `L1 = 10µH`（NR4018T100M） | UC8179 应用笔记推荐 **1.5µH**（SRN2010TA-1R5Y），两者矛盾；做升压电路时不能照这个 BOM |
| 8 | **P4** | “Waveform stored in **flash memory**” | UC8179 的波形在 **OTP**，不是可反复写的 flash |
| 9 | **P52** | 页码写成 “Page **52** of 51” | 复制粘贴痕迹 |
| 10 | **P4** | `Weight 270.5 g` | 5.83" 模组通常 30g 量级，270.5g 明显异常（疑似 27.05 或 70.5 的笔误） |
| 11 | **P4** | 像素间距 0.1833×0.1833，但有效区 88.22/480=0.18379 | 纵向间距与标称值差约 0.25%，属小瑕疵 |
| 12 | **P38~40** | 8-4 号称 “AC Characteristics”，实际只有 3/4-wire、dual SPI 的格式图，**没有 TSCYC/TSHW 等时序数值** | UC8179 P58~59 有完整时序表；HINK 正文里搜不到 |

这些错误里，**#1/#2** 影响最直接：如果你按 P48 的“外形 170.2×111.2”做外壳，会差一大截；实际应按 P4 的 125.4×99.5。

## 4. 最坑驱动的一点：HINK 写的是“IC 复位默认值”，不是你屏的 OTP 值

HINK 的寄存器默认值抄自 UC8179（IC 出厂默认），但这块屏在出厂时用 OTP 改写了其中一部分
（OTP `0x000C=0xA5`，命令默认值功能已启用）。两者对比如下：

| 寄存器 | HINK/UC8179 文档“默认” | 本屏 OTP 实际值 | 直接照文档写会怎样 |
|---|---|---|---|
| PSR `0x00` | `0x0F`：KW/R=0（**三色 KWR**）、UD=1 | `0x17`：KW/R=1（**黑白 KW**）、UD=0 | 进三色模式，黑白图会发灰/偏色 |
| TRES `0x61` | 800×600：`03 20 02 58` | 648×480：`02 88 01 E0` | 分辨率错，画面撕裂或只显示一部分 |
| GSST `0x65` | HST=0 | **HST=16** | 整幅图左移 16 像素（右边少 16 列） |
| PWR `0x01` | VDH/VDL=`0x3A`=14.0V | `0x3F`=**15.0V** | 对比度偏低、发灰 |
| PWR | VDHR=`0x03` | `0x12`（6.0V） | 黑白模式影响小，三色模式影响大 |
| BTST `0x06` | `17 17 17 17` | `CF CF 26 17` | 升压软启动不同，上电浪涌/稳定性变差 |
| CDI `0x50` | `0x31 0x07`（双平面 NEW/OLD） | `0x10 0x07`（本库默认改 `0x12` 单平面） | 数据组织方式不同；单平面可少发一半数据 |
| VDCS `0x82` | `0x00`（-0.10V） | TR0 里是 `0x12`（**-1.00V**） | 对比度明显不足 |
| TCON `0x60` | `0x22` | `0x22` | 一致 ✔ |
| CDI 时钟 `0x07` | `0x07` | `0x07` | 一致 ✔ |

> 这些“默认值”作为寄存器复位值本身没错，错在**它们不是这块屏的配置**。
> 驱动必须以 OTP 为准；HINK 文档只适合拿来核对指令格式。

## 5. 关于你看到的“上下镜像”

OTP 的 PSR 是 `0x17`（UD=0，向下扫描），实机点亮确实是上下颠倒；
把 UD 翻成 1（`0x1F`）就正了。而 HINK/UC8179 文档里 PSR 默认 `0x0F` 恰好也是 UD=1。

这说明：

- 文档默认的**扫描方向**（UD=1）与你的实际安装方向一致；
- 但文档默认的**色彩模式**（KW/R=0 三色）与这块屏（KW/R=1 黑白）不一致。

所以 **PSR 不能整字节照抄**：方向位该听实测，模式位该听 OTP。库里已经拆开处理：
`PSR = OTP 值 | UD 取反`。

## 6. 到底该信谁

| 内容 | 优先级 |
|---|---|
| 分辨率 / 扫描起点 / 波形 / 驱动电压 / VCOM / 温度分档 | **板载 OTP**（最权威，本屏专用） |
| 指令码、寄存器位定义、LUT 格式、SPI 时序 | **UC8179 手册**（IC 原厂） |
| 机械尺寸、FPC 引脚、光学、可靠性、包装 | **HINK 手册**（但 P47~52 不要用） |
| 方向/极性这种“装配相关”参数 | **实测**（用 HelloWorld 串口键调） |

HINK 的指令表可以拿来交叉验证 UC8179，但**不要用它的默认值初始化**，也不要用它的
P47~52 做结构件。

## 7. 附：这次比对是怎么做的

1. 用自写的 PDF 文本提取器（`tools/pdf_extract.py`，支持 PDF 1.5 压缩对象流）
   把两份手册转成文本：`tools/uc8179_text.txt`、`tools/hink_text.txt`。
2. 取两份文档“命令表”区域的十六进制码，按出现顺序去重比对：
   - UC8179：59 个码
   - HINK：59 个码
   - 差集为空，顺序一致（含 DSLP 的 `0xA5`）。
3. 逐节核对默认值、位定义、TRES/GSST 示例、电气参数、机械尺寸。
4. 用 OTP 解析结果（`tools/uc8179_otp_parser.py`）对照分辨率、HST、VDH/VDL、VCOM。

## 8. 对现有驱动库的影响

`UC8179_EPD` 的 `UC8179_PanelProfile.h` 全部由 OTP 生成，不受 HINK 文档错误影响：

- 648×480、HST=16、VDH/VDL=0x3F、VCOM=0x12、PSR=0x17、TCON=0x22、BTST=CF/CF/26/17；
- 默认 `PSR=0x1F`（UD 取反，实测修正），可用 `-DUC8179_DEFAULT_PSR=0x17` 回到原始 OTP 值；
- 默认单平面（CDI=0x12），可用 `setSinglePlane(false)` 回到双平面。

需要重新读一块新屏的 OTP 时，跑：

```bash
python extras/uc8179_otp_parser.py extras/HINK-E0583A51-A0_OTP.txt \
       --header src/UC8179_PanelProfile.h --name HINK-E0583A51-A0
```
