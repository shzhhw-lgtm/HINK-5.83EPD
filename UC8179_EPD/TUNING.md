# 如果我来配：从 OTP 出发的调参方案

> 目标场景：bigclock 四屏时钟，室内使用，每分钟刷新一次，要求四片一致、长期稳定。

---

## 0. 五条原则

1. **OTP 是厂家在这块玻璃上标定过的**，默认全信。它不是“出厂默认值”，是这块屏的专用配置。
2. **只改 OTP 没管的东西**：方向、数据平面、时序、边框。电压/波形/帧率优先让 OTP 管。
3. **改之前先证明这个寄存器真的有用**（可控性探测）。OTP 波形可能覆盖主机写的电压/帧率。
4. **一次只改一个变量**，固定测试图，记录刷新毫秒 + 观感。
5. **生产配置落在 OTP 的温区内**。TR6/TR7 是 80~127°C 的高温波形，不要当“高质量档”常温硬用。

---

## 1. 先分清“谁拥有”这些参数

| 参数 | 归属 | 依据 |
|---|---|---|
| 波形 LUT（7 组状态） | **OTP**（按 TR 选） | PSR.REG=0 |
| VDH / VDL / VDHR | **OTP TR**（每档一套） | TR 字节 0x004A~0x004C |
| VCOM_DC | **OTP TR**（TR0~5 是 -1.0V，TR6/7 是 -2.0V） | TR 字节 0x004E |
| 帧率 | **OTP TR**（50/60/70Hz） | TR 字节 0x0049 |
| 温度分档边界 | **OTP** | 0x0001~0x000B |
| 方向 UD/SHL | 主机（PSR） | 装配相关 |
| 单/双平面 DDX | 主机（CDI） | 数据传输方式 |
| CDI 间隔、TCON | 主机 | 时序 |
| 边框 LUT、EVS、PWS、LVSEL、BTST | 主机 | 电源/边框 |
| 分辨率、HST | OTP 默认（主机可写但别动） | TRES/GSST |

> **推论**：在 PSR.REG=0 下，`setSourceVoltage()`、`setVcomDc()`、`setFrameRateCode()`
> 很可能被 OTP TR 覆盖。是否真的有效，必须先做 §2 的探测。

---

## 2. 可控性探测（上机第一小时）

目的：用“极端值”判断每个寄存器是否真的影响画面，避免在无效旋钮上浪费时间。

| 试探 | 设置 | 如果有效会看到 | 如果没反应说明 |
|---|---|---|---|
| VCOM | `v0x00`（-0.1V）vs `v0x30`（-2.5V） | 对比度明显变化 | OTP TR 接管了 VCOM |
| VDH/VDL | `h0` `l0`（2.4V） | 画面明显变淡/发白 | OTP TR 接管了源压 |
| 帧率 | `f1`（10Hz，约 12s） | 刷新时间约 5 倍 | OTP TR 接管了帧率 |
| CDI | `c0` vs `c15` | 边缘/拖影有差异 | CDI 被忽略（可能性低） |
| TCON | `setTcon(0x00)` vs `0xFF` | 细线串扰有差异 | TCON 被忽略（可能性低） |
| EVS | `e0` vs `e3` | 只有边框变化 | — |
| 平面 | `s` | 传输时间翻倍/减半 | — |

把结果记下来，后面只调“有效”的项。`04_ParamLab` 里按 **`P`** 会自动跑这 6 项并记录结果。我的预期是：
**VCOM/VDH/帧率很可能无效，CDI/TCON/EVS/平面有效**——但以实测为准。

### 实测结论（2026-11，TR4，REG=0）

| 试探 | 结果 | 结论 |
|---|---|---|
| VCOM 0x00 | refresh/画面无变化 | `VDCS` 被 OTP TR 覆盖 |
| VDH/VDL 2.4V | 无变化 | `PWR` 被 TR 覆盖 |
| FRS 10Hz | refresh 仍 579ms | `PLL` 被 TR 帧率覆盖 |
| CDI 2hsync | 写入生效，但整帧差异很小 | 时序可调，收益有限 |
| TCON 0x00 | 同上 | 时序可调，收益有限 |
| 双平面 | display +80ms（DTM1 数据），画面无差异 | 平面切换生效 |

**所以在 `PSR.REG=0` 下，真正还能调的是：TR 档、边框 LUT/EVS/Hi-Z、单/双平面、方向、TSE 偏移。**
电压和帧率想改，只能走 `PSR.REG=1` + 自己写全套 LUT，工作量和风险都大。

## 3. 我的基线配置（全部来自 OTP，只改方向）

| 寄存器 | 值 | 理由 |
|---|---|---|
| PSR `0x00` | `0x1F` | OTP 是 `0x17`；只把 UD 取反修正上下颠倒 |
| PWR `0x01` | `07 17 3F 3F 12` | OTP TR0：VDH/VDL=15V，VDHR=6V，VG=±20V |
| BTST `0x06` | `CF CF 26 17` | OTP |
| PLL `0x30` | `06` | 50Hz；实际很可能被 TR 覆盖 |
| CDI `0x50` | `12 07` | DDX=10 单平面，CDI 10 hsync |
| TCON `0x60` | `22` | OTP |
| TRES `0x61` | `02 88 01 E0` | 648×480 |
| GSST `0x65` | `00 10 00 00` | HST=16 |
| EVS `0x52` | `02` | 默认（BDEND=VCOM_DC） |
| VDCS `0x82` | **不写** | 交给 OTP TR，避免和 TR 的 VCOM 打架 |
| PWS `0xE3` | `88` | OTP |
| LVSEL `0xE4` | `03` | OTP |
| TSE `0x41` | `00` | 内部温度传感器，偏移 0 |
| TSFIX/TSSET | `0 / 关` | 自动按温度选 TR |

这就是库当前 `begin()` 的默认值——也是我会直接拿去跑一周的配置。

## 4. TR 怎么选：AUTO，但知道自己在哪个档

面板工作温区是 0~50°C，和 OTP 分档的交集：

| 环境温度 | 自动选中 | 帧率 | VCOM |
|---|---|---|---|
| 0~5°C | TR0 | 50Hz | -1.0V |
| 5~10°C | TR1 | 50Hz | -1.0V |
| 10~15°C | TR2 | 50Hz | -1.0V |
| 15~20°C | TR3 | 50Hz | -1.0V |
| 20~30°C | TR4 | 60Hz | -1.0V |
| 30~50°C | TR5 | 70Hz | -1.0V |
| >50°C（超规格） | TR6/TR7 | 50Hz | **-2.0V** |

结论：

- **常温下只会用到 TR0~TR5**，它们电压一致（±15V / -1.0V），只有帧率不同。
- **TR6/TR7 是高温波形**（-2.0V VCOM），在 25°C 强行用属于超温区使用。
  看起来可能更黑，但这是用错温区的补偿量，长期残影/离子极化风险未知，**我不会把它作为生产配置**。
- AUTO 的唯一小问题是 20°C / 30°C 边界会换档（50↔60↔70Hz），
  观感差异很小；如果实测发现明显跳变，再考虑固定 TR4（前提是环境长期在 20~30°C）。

### 实测刷新时间（21°C，648×480，S1 单平面）

| 档 | 强制码 | refresh |
|---|---:|---:|
| TR0 | 0x05 | 1021 ms |
| TR1 | 0x0A | 980 ms |
| TR2 | 0x0F | 837 ms |
| TR3 | 0x14 | 817 ms |
| TR4 | 0x1E | **579 ms** |
| TR5 | 0x50 | **575 ms** |

- 50Hz 的 TR0~TR3 在 0.8~1.0s；60/70Hz 的 TR4/5 约 0.58s，快约 30%。
- 20°C 边界会在 TR3/TR4 之间跳（817 vs 579ms）。实测 21°C 时仍有刷新落在 817ms，
  说明芯片是在 PON 时采样温度，和事后读 TSC 可能差 1°C。
- 四屏时钟想稳定的话，20~30°C 环境直接固定 TR4；不在这个温区就还是用 AUTO。

接上回读后可以直接读：`readTemperature()` + `currentTrGear()`（ParamLab 按 `i` 或看参数行）。
没接回读时只能看 `lastRefreshMs()` 反推：TR4(60Hz) 比 TR3(50Hz) 快约 15~20%。

## 5. S1 还是 S0：我会选 S1

OTP 的 CDI 默认是 `0x10`（DDX=00，NEW/OLD 双平面），这是给“真有上一帧”的差分刷新设计的。

但我们没有保存上一帧。如果按双平面刷，只能把 OLD 补成白色——这是**假差分**，
像素真实状态和控制器以为的不一致，波形反而可能不对。

所以全刷我会用 **S1（CDI=0x12，DDX=10，只发 NEW）**：

- 每次都是绝对刷新，不依赖历史；
- 数据量减半（4 屏省约 0.3s）；
- 代价是失去“未变化像素走 WW/KK 短波形”的优化——全刷本来就要整屏驱动，影响不大。

如果哪天要做真正的差分/局刷，再引入 38KB 影子帧，回到 S0。

## 6. 测试矩阵（我会怎么验证）

**温度点**：5°C / 25°C / 45°C（面板规格 0~50°C 的三个代表点）。
不能控温时，至少记录室温，并用 `setTemperatureOffset()` 模拟换档（只测波形，不测玻璃响应）。

**图案**：纯黑、纯白、1px 棋盘、2px 棋盘、1px 横竖线、大小字、1px 边框。

**指标**：
1. 黑度/白度（同机位拍照，比灰度）；
2. 残影（棋盘→全白，看残留）；
3. 1px 线是否连续、是否发虚；
4. `lastRefreshMs()`；
5. 边框是否发灰/发黑。

**做法**：每档重复 3 次取中位；一次只改一个参数；每次按 `p` 看参数、按 `l` 输出一行 CSV 便于抄表。

**边界测试**：在 20°C 附近来回（比如空调调温），看 AUTO 换档那一下是否可见。

---

## 7. 我不会做的事

- 不写 `PSR.REG=1`（寄存器 LUT）——除非准备完整的 5 组 LUT，否则白屏。
- 不把 VDH/VDL 往上拉——6 位码最大就是 15.0V，已经在 OTP 值。
- 不为了“更黑”长期用 TR7；那是 90~127°C 的波形。
- 不在没做可控性探测前改 VCOM/帧率。
- 不动 BTST，除非上电花屏/电流异常。
- 不用局部刷新（OTP 没有专用局刷波形）。
- 不频繁强制 TR 切换（每次切换都是一次完整波形，没意义）。

---

## 8. 一页结论

> **配置 = OTP 原样 + 只改方向（UD）+ 单平面（S1）+ 自动 TR。**
> 其他先不动；用 `04_ParamLab` 做一次可控性探测，确认哪些旋钮真的有效，
> 再只对“有效且有问题”的项做微调。

如果只能记一句话：
**先证明寄存器有效，再谈调参；OTP 的温区不是建议值，是边界。**

## 9. 附：边框/白底发灰的排查顺序

1. **先排除残影**：`t7` 固定 TR7，`w` 刷全白，`k` 再画测试图。TR7 的 VCOM 是 -2.0V、波形更长，通常能把白态写透。
2. **只有边框灰**：换 Border LUT——`b0`(LUTBD) / `b1`(LUTKW，OTP 默认) / `b2`(LUTWK) / `b3`(LUTKK)；
   再试 `e0`(BDEND=0V) / `e2`(VCOM_DC) / `e3`(floating)，以及 `z` 打开边框 Hi-Z。
3. **整片白底灰**：多半是白态没写透。先 TR7 多刷一次；如果 `P` 探测证明 VCOM 有效，再把 VCOM 往负调 1~2 码。
4. **黑白交替后发灰是正常的**：鬼影测试本身就是制造残影，最终必须用 TR7 收尾再评估。

> 注：`P` 向导不再调用软复位（软复位后命令可能被忽略，导致 PON 卡死），
> 改为直接重写全部寄存器，并把 VDCS 显式写回 0x00。
